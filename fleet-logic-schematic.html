modServiceable · CalculateDeployable(ws, rowNum, vehicleType)

1 · Is the vehicle deployable?

Every row is checked unless the vehicle type ignores it (DisregardConfig). If any row is HIGH, the big NOR goes LOW and DEPLOYABLE is left blank, which the system reads as NOT AVA.

DEPLOYABLE = NOT( Σ blocked_i · ¬ignored_i + Σ maint_j · ¬ignored_j ) blocked_i = cell has any text (VOR STATUS: text contains "X") maint_j = cell = "N" (Y and blank both count as pass) result = "AVA" when HIGH, "" (blank) when LOW
Blank maintenance counts as a pass

Only an N blocks a vehicle. An item nobody filled in does not. Try the "Maintenance cells blank" preset.

VOR needs an X

VOR STATUS only blocks when the text contains an X. Something like DONE leaves the vehicle deployable. Click VOR STATUS three times to see this.

Any text blocks

TASKING, SELF DRIVE, TLOAN, OVERSEAS and STANDBY block on any text at all, even a single space-free word.

Disregards mask a row

Pick MB 290 GS, then set AIRCON = N. The ignore pin forces that AND gate LOW, so the vehicle stays AVA.

modDashBoard · RenderDashboard (per vehicle)

2 · Where each vehicle shows up on the dashboard

RenderDashboard runs these gates once for every vehicle. Every vehicle also goes into the Maintenance Schedule table, so that table has no gate.

"Any blocked field has text" here reads the raw cells, without disregards. So a vehicle that is NOT AVA only because of a maintenance N does not appear in the Daily Status table.
